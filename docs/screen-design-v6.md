# rs-term 画面設計 v6

日付は 2026-11-10。`docs/design-v6.md` と対になる文書で、見た目と文言の正である。寸法はすべて GPUI の論理 px（表示倍率 100% のときの px）。色は 16 進。見本は `/workspace/rs-term-mock/s1..s4` で、色と寸法の多くはそのモックの `base.css` から取った。ワイヤーフレームは `docs/wireframes/*.svg`（§7）。

## 1. 配置と寸法

### 1.1 ウィンドウ

### 1.2 ペイン

ペインの矩形は design §3 の木から計算する。クライアント領域全体をルートの矩形とし、分割ごとに比率で 2 つに割る。

| 項目 | 値 |
| --- | --- |
| ペイン同士の隙間（仕切りの見た目） | 2 px、色 `#3b3d45`。外周には隙間を置かない |
| 仕切りの当たり判定 | 隙間の中心から ±3 px（計 6 px）。カーソル：左右分割 `col-resize`、上下分割 `row-resize` |
| 仕切りのホバー、ドラッグ中 | 隙間を `#4a8cff` で塗る |
| ペインの背景 | `#1e1f24`（ダーク）／ `#ffffff`（ライト）。端末パレットの背景色 |
| フォーカス枠 | フォーカス中ペインの内側 1 px、`#4a8cff`。状態行も枠の内側に入る。ペインが 1 枚でも描く |
| 端末領域の余白 | 上下 8 px、左右 10 px |
| 端末領域 | ペイン高 − 状態行 24 px − 余白 16 px |
| 最小ペイン | 比率 0.1〜0.9 を守ったうえで、極端に小さい窓では列 1・行 1 まで縮む。グリッドは切り詰めて描く |

## 3. 状態行

### 3.1 欄の書式

左から次の順に並べる。空の欄は詰め、間隔は 14 px のまま。

| # | 欄 | 書式 | 色 |
| --- | --- | --- | --- |
| 1 | モードバッジ | `PREFIX` / `RESIZE` / `COPY` / `ZOOM`。フォーカス中ペインだけ。PREFIX、RESIZE、COPY は同時に 1 つ。ZOOM はそれらと並べて出す | §2.1 のバッジ色 |
| 2 | ペイン名 | `[名前]`。最大 16 文字、超えたら「…」 | 状態行文字色、太字 |
| 3 | 接続 | 点 + ポート名 + 補足（§3.2） | 点は §3.2、文字は状態行文字色 |
| 4 | 速度とフレーム | `{baud} {data}{parity}{stop}`。例 `115200 8N1`、`9600 7E1`。ポート未選択なら `—` | 文字色 |
| 5 | フロー | `Flow: None` / `Flow: XON/XOFF` / `Flow: RTS/CTS（送信のみ）`。ポート未選択なら `—` | 文字色 |
| 6 | エンコーディング | `UTF-8` / `Shift_JIS` | 文字色 |
| 7 | 付帯 | ローカルエコー時 `ECHO`。改行が既定（受信 Auto、送信 CR）と違うとき `改行 受信:{CR/CRLF/LF/Auto} 送信:{CR/CRLF/LF}`。DTR オン時 `DTR` | 文字色 |
| 8 | ログ | 下表 | 下表 |
| 9 | メッセージ | `エラー: 本文` / `注意: 本文` / `本文`。残りの幅、はみ出しは末尾「…」 | 赤 / 黄 / 文字色 |

ログ欄：

| ログの状態 | 表示 | 色 |
| --- | --- | --- |
| 停止 | `LOG off` | 文字色 |
| テキスト記録中 | `● LOG text HH:MM:SS`（開始からの経過、99 時間超は `99:59:59+`） | 赤 `#e06c75` |
| バイナリ記録中 | `● LOG bin HH:MM:SS` | 赤 |
| 一時停止 | `LOG 一時停止 HH:MM:SS`（経過は止める） | 黄 |
| 失敗 | `LOG 失敗` と、メッセージ欄にエラー | 赤 |

幅が足りないときは、メッセージが 160 px 以上残るまで 7 → 5 → 6 → 4 の順に欄を消す（design §5.2）。それでも足りなければメッセージを切る。メッセージが無いときは欄を消さない（足りなければ右端で切る）。

### 3.4 グリッドの重ね描き

未接続で、そのペインが一度も受信していない（グリッドが空）とき、端末領域の左上（余白の内側）に `（未接続）  Ctrl+Shift+K で接続` を端末フォント 14 px、色 `#7a7d86` で描く（s3、s4）。`Term` には入れない。キー入力では消えない。最初の受信か接続成功で消える。

## 4. パレットのページ

共通の決まり：

- 各ページはヘッダ（パンくず）、検索欄、行、フッタの順。ヘッダ、プレースホルダ、フッタ、空表示の文言は下の各表のとおり。
- 行は「ラベル（補足）……キー または ✓」。補足が「—」の行は補足を出さない。
- 初期の選択行：ルートは先頭、値を選ぶページは現在値の行（無ければ先頭）。
- 検索は部分一致（大文字小文字無視）。対象はラベルとキーワード。キーワードは表に書いたもの + アクション ID。
- ページに入るたびクエリは空。

### 4.2 接続（5 ページ）

フッタは全ページ共通：`Enter で次へ（ボーレート → フレーム → フロー → DTR）/ Esc で戻る`。最終ページだけ `Enter で接続 / Esc で戻る`。

**1/5 ポート**

| 項目 | 文言 |
| --- | --- |
| ヘッダ | `接続 › ポート` |
| プレースホルダ | `ポートを検索（COM 番号、製品名）` |
| 空表示（検索で 0 件） | `一致するポートが無い` |

行：`list_ports` を COM 番号の昇順。ラベル `COMn`、補足は USB の製品名（`SPDRP_FRIENDLYNAME` から末尾の ` (COMn)` を除く）、無ければ種別（`Bluetooth`、`PCI`、`種類不明`）。USB でシリアル番号があれば補足の後ろに ` SN:xxxx`。キーワードは VID:PID（`0403:6001` の形）。
ポートが 0 件のとき：確定できない行を 1 行 `ポートが見つからない（USB を挿すと 1 秒以内に出る）`（文字 `#8b8f99`、選択されない）。
接続中のペインで開いたとき、このページの前に確認ページ：ヘッダ `接続 › 確認`、行 1 `すでに COM3 に接続中。切断してから選び直す`、行 2 `やめる`、初期選択は行 2。

**2/5 ボーレート**：ヘッダ `接続 › ボーレート`、プレースホルダ `ボーレートを選ぶか数値を入力`、空表示 `1〜4000000 の整数を入力`。行：（クエリが 1〜4000000 の整数のとき先頭に `この値を使う：{n}`）、`9600`、`19200`、`38400`、`57600`、`115200`、`230400`、`460800`、`921600`。

**3/5 フレーム**：ヘッダ `接続 › フレーム`、プレースホルダ `フレームを検索（例：7E1）`、空表示 `一致するフレームが無い`。行（ラベル、補足）：`8N1`（8 ビット・パリティなし・ストップ 1）を先頭に、続けて `8N2 8E1 8E2 8O1 8O2 7N1 7N2 7E1 7E2 7O1 7O2 6N1 6N2 6E1 6E2 6O1 6O2 5N1 5N2 5E1 5E2 5O1 5O2`。補足は同じ書式で「{d} ビット・パリティ{なし/偶数/奇数}・ストップ {1/2}」。

**4/5 フロー**：ヘッダ `接続 › フロー`、プレースホルダ `フロー制御を選ぶ`。行：`None`（フロー制御なし）、`XON/XOFF`（ソフトウェア）、`RTS/CTS（送信のみ）`（CTS による送信制御。受信の自動 RTS はしない）。

**5/5 DTR**：ヘッダ `接続 › DTR`、プレースホルダ `開くときの DTR`。行：`オフ`（既定。開くとき DTR を触らない）、`オン`（開いた後 DTR を上げる）。確定で接続を始めてパレットを閉じる。

## 5. フォーカスの規則

1. キーボードのフォーカスは常に「フォーカス中ペイン」か「パレットの検索欄」のどちらか 1 つ。
2. 起動時はフォーカス中ペイン（layout.toml の `focus`、無ければ唯一のペイン）。
3. パレットを開くと検索欄。閉じるとフォーカス中ペイン（クリックで閉じたときはクリックしたペイン）。
4. 分割：新しいペイン。閉じる：直前のペイン → 行きがけ順の次 → 前（design §3.3）。
5. 入れ替え：元のペインのまま（位置が変わる）。
6. ズーム中の方向移動：移った先がズーム表示になる。
7. フォーカス枠（1 px `#4a8cff`）とモードバッジはフォーカス中ペインだけ。パレット表示中も枠は残す（どのペインに効くかを示す）。
8. 窓が非アクティブのときも枠は残す。キャレットは非表示。
