# rs-term 設計 v7

日付は 2026-11-11。対象はリポジトリ `sotola122/rs-term` のブランチ `feat/rs-term-tui`。起点は `fix/rs-term-v1-herdr` の `51e1149`。著作権者は sotola122（`Copyright 2026 sotola122`、Apache-2.0）。

この文書は v6（`docs/design-v6.md`、`docs/screen-design-v6.md`）の GUI 部分を置き換える。v6 のファイルは履歴として残す。シリアル、コーデック、画面エミュレーション、ログ、`settings.toml` の schema 1 は v6 から引き継ぐ。コードとこの文書が食い違えば、この文書に合わせてコードを直す。

識別子は英語、説明は日本語である。

## 0. 決定

所有者の指示は次のとおりである。

- gpui ではなく TUI にする。
- ペイン、分割、タブは rs-term が持たない。herdr、tmux、Windows Terminal が担当する。
- 方式は ratatui の全画面である。tio のようなパススルー（ホスト端末のスクロールバックに生バイトを流す方式）ではない。

1 プロセスは 1 シリアルセッションである。複数の接続が欲しければ、利用者が rs-term を複数起動する。

## 1. 範囲

### 1.1 やること

- Linux と Windows で動く全画面シリアル端末。
- 画面は `rs-term-core` のスクリーンバッファを描画し、下端に状態行を 1 行置く。
- 自前のスクロールバック。マウスホイールと PgUp / PgDn（Shift の有無は同じ）。
- マウス選択とコピー（OSC 52 と、取れるときは OS のクリップボード）。ペースト。
- プレフィックスキー（既定 Ctrl+A、変更可）。2 回押すと対応する制御バイトを送る。続く 1 打鍵で接続、切断、再接続、ブレーク、ログ開始、ログ停止、文字列送信、ファイル送信、ボーレート変更、エンコーディング変更、ヘルプ、終了。入力は ratatui のモーダルダイアログ。
- キーからバイトへの変換（矢印、ファンクション、Ctrl、日本語 IME の確定文字）。リサイズ。パニックと終了で端末を戻す。
- 受信はバーストでもバイトを捨てない。

### 1.2 やらないこと

- ペイン、分割、タブ、ズーム、仕切りのドラッグ。
- コマンドパレット。gpui、gpui-component、gpui-kit。
- メニュー、ツールバー、設定ウィンドウ。
- ホスト端末の代替バッファを使わないパススルー表示。
- ISO-2022-JP。
- macOS は二次。コードは Unix 系として動く想定だが、検証の対象は Linux と Windows の CI、および Linux 上の pty である。

## 2. クレート

| クレート | 役割 |
| --- | --- |
| `rs-term-core` | シリアル、コーデック（Shift_JIS / UTF-8）、VTE 画面、セッション、ログ、設定、日本語のエラー。GPUI に依存しない。この版でも UI を知らない |
| `rs-term` | ratatui + crossterm の全画面フロントエンド。1 つの `Session` だけを持つ |

`rs-term` から削除するものは、ペイン木（`layout.rs`、`layout_store.rs`）、herdr キーマップ（`keymap.rs`）、パレット、ワークスペース、gpui の依存である。

依存の版はワークスペースで固定する。UI は `ratatui` 0.30（既定の crossterm バックエンド）と、同じメジャーの `crossterm` である。クリップボードの補助に `arboard` を使う。取れない環境では OSC 52 だけが成功すればよい。

ツールチェーンは `rust-toolchain.toml` の 1.95.0 のままである。`rust-version` も 1.95 のままである。

## 3. CLI

```text
rs-term [PORT] [OPTIONS]
```

`PORT` は位置引数で、最大 1 つ。フラグの前後どちらでもよい。省略したときは TUI のポートピッカーを出す。

| フラグ | 意味 | 既定 |
| --- | --- | --- |
| `-b`, `--baud` | ボーレート（1〜4000000） | 115200。`settings.toml` があればその値 |
| `--data` | 5 / 6 / 7 / 8（または five / six / seven / eight） | 8 |
| `--parity` | none / odd / even（n / o / e も可） | none |
| `--stop` | 1 / 2（one / two も可） | 1 |
| `--flow` | none / xonxoff / rtscts | none |
| `-e`, `--encoding` | sjis / shift_jis / utf8 / utf-8 | sjis |
| `--log PATH` | 起動直後からテキストログをこのファイルへ書く | なし |
| `--prefix SPEC` | プレフィックス。`ctrl-a`、`ctrl+a`、`C-a` | ctrl-a |
| `-h`, `--help` | 使い方を出して終了コード 0 | |

`settings.toml`（schema 1）が読めれば、シリアル、改行、エンコーディング、スクロールバック行数、ローカルエコー、ログのディレクトリとテンプレートの既定にする。CLI はその上書きである。ファイルが無い、または壊れているときは、組み込みの既定で起動し、壊れているときだけ状態行に日本語の理由を出す。schema は上げない。未知のキーでファイル全体を拒む v6 の規則は維持する。

使い方の誤りは標準エラーへ日本語で書き、終了コード 2 で終了する。TUI はまだ開かない。

`--log` の `PATH` はファイルである。親ディレクトリが無ければ作る。起動時にテキストログを開始し、失敗したら状態行に理由を出してセッション自体は続ける。

プレフィックスに指定できるのは Ctrl と、制御コードに対応する 1 文字（英字、および `@`、`[`、`\`、`]`、`^`、`_`、`?`）である。それ以外は起動時に拒む。

## 4. 画面

全画面（代替スクリーン）である。レイアウトは縦に 2 つだけである。

1. 端末領域。残り全部。`Session::screen_content` のセルを、左上から行優先で描く。幅 0 のスペーサセルは描かない。幅 2 の文字は 1 セルとしてその文字を出す。色は設定のパレット（既定 `classic-dark`）と、スナップショットの 256 色上書きから決める。反転、太字、下線、選択を反映する。カーソルが見えていてビューが最下端にあるときは、そのセルを反転する。
2. 状態行。高さ 1。内容は左から、プレフィックス中なら `PREFIX`、ポート（未選択なら「未選択」）、フレーム（例 `115200 8N1`。フローが none 以外のときだけフロー名を続ける）、エンコーディング（`Shift_JIS` または `UTF-8`）、接続状態、ログ状態、`RX` バイト数、`TX` バイト数。状態行のメッセージがあるときは右端に付ける。幅が足りなければメッセージを `…` で切り、左の項目は残す。

接続状態の語は次のとおりである。

| リンク | 語 |
| --- | --- |
| ポート未選択、または利用者が切断 | 未接続 |
| オープン待ち | 接続中 |
| オープン中 | 接続 |
| 相手または OS が切った | 喪失 |

ログ状態の語は `LOG off`、`LOG on`（テキスト）、`LOG bin`、`LOG 一時停止`、`LOG 失敗` である。

RX は `apply_rx` が受け取ったバイト数、TX はポートへキューしたバイト数（キー、ペースト、端末応答）である。捨てたバイトは数えない。この版では受信を捨てない。

エラー、注意、案内は状態行に日本語で出す。別ウィンドウには出さない。重大度は v6 と同じ（案内はそのまま、注意は黄色、エラーは赤）である。

プレフィックス中はポートへ何も送らない。状態行の左に `PREFIX` を出す。

## 5. スクロールバック、選択、コピー、ペースト

スクロールバックは `rs-term-core` の `Screen`（alacritty の `Term`、`terminal.scrollback`、既定 10000 行）である。ホスト端末のスクロールバックは使わない。代替スクリーンに入るので、ホストはスクロールしない。

| 操作 | 動作 |
| --- | --- |
| ホイール上 | `scroll_lines` の正の delta（履歴方向）を 3 行 |
| ホイール下 | 負の delta を 3 行 |
| PgUp、Shift+PgUp | `scroll_page(true)` |
| PgDn、Shift+PgDn | `scroll_page(false)` |

これらのキーとホイールはポートへ送らない。ビューが最下端で無いときも受信はバッファへ入り、描画は `display_offset` の領域を出す。新しい行でオフセットを 0 に戻さない。

選択は端末領域の左ドラッグである。離したとき、選択文字列が空でなければコピーする。コピーは常に OSC 52（`ESC ] 52 ; c ; <base64> BEL`）をホストへ書く。加えて OS のクリップボードへ書けたときだけ書く。失敗しても状態行にエラーは出さない（OSC 52 が本線である）。

ペーストは次の 2 つである。

- ホストのブラケットペースト（`Event::Paste`）。`Input::Text` として送る。改行はセッションの送信改行に変換する。
- プレフィックスの次の `p`。OS のクリップボードが読めれば、同じく `Input::Text` で送る。読めなければ状態行に「クリップボードを読めない」と出す。

モーダルを出しているあいだ、ホイールと選択は無視する。

## 6. プレフィックスとダイアログ

既定のプレフィックスは Ctrl+A である。v6 の Ctrl+B は herdr のプレフィックスだった。この版の rs-term は herdr や tmux の内側で動くので、外側が使う Ctrl+B を奪わない。Ctrl+A は GNU screen の慣例であり、`--prefix` で変えられる。

状態は 3 つである。通常、プレフィックス待ち、モーダル。時間切れは無い。

通常のとき、プレフィックスはポートへ送らず、プレフィックス待ちへ移る。それ以外のキーは §7 のとおりポートへ送る。

プレフィックス待ちの次の 1 打鍵は次のとおりである。未記載のキーは捨てて通常へ戻る。ポートへは送らない。

| 打鍵 | 動作 |
| --- | --- |
| プレフィックス自身 | 対応する制御バイトを 1 バイト送る。Ctrl+A なら `0x01`。未接続なら送らず、状態行に理由を出す |
| Esc | 通常へ戻る。何も送らない |
| `c` | 接続。パスが無ければポートピッカー。既に接続中なら「すでに接続している」 |
| `d` | 切断。画面は残す |
| `r` | 再接続。パスが無ければピッカー。あれば一度切って同じ設定で開く |
| `b` | ブレークを 250 ms |
| `l` | ログ開始。すでにログ中なら開始しない。ダイアログに既定パスを入れておく |
| `L` | ログ停止 |
| `s` | 文字列を送るダイアログ |
| `f` | ファイルを送るダイアログ |
| `u` | ボーレートのダイアログ |
| `e` | エンコーディングのダイアログ |
| `p` | クリップボードをペースト |
| `?` | ヘルプを出す |
| `q` | 終了 |

ダイアログは ratatui の枠付きモーダルである。Enter で確定、Esc で取消。文字とバックスペースとペーストを受け付ける。ポートへは、確定するまで送らない。

ポートピッカーは、起動時に `PORT` が無いときと、`c` / `r` でパスが無いときに出す。`list_ports` の一覧と、1 行の入力を同時に出す。入力は一覧のフィルタである。上下で選択を動かす。Enter のとき、入力が空でなければその文字列をパスとして開く（一覧に無くてもよい。`/tmp/ttyV0` のような任意パスを許す）。入力が空なら、選択中の一覧項目を開く。一覧が空で入力も空なら何もしない。列挙に失敗しても、入力したパスでは開ける。

文字列送信は、入力の末尾に送信改行を 1 つ足して `Input::Text` で送る。ファイル送信はバイト列のまま送る。長さがセッションの送信上限（16 MiB）を超えるときは、読む前に拒み、1 バイトも送らない。ボーレートは 1〜4000000 の整数で、接続中ならポートへ適用し、拒まれたらコアが元の値へ戻す。エンコーディングは `sjis` または `utf8`（§3 と同じ綴り）である。

ログ開始ダイアログの既定パスは、§9 のログディレクトリに、`settings.toml` の `name_template`（既定 `{port}_{date}_{time}.log`）を展開したファイル名を足したものである。テキスト、UTF-8、追記しない、プレーン（画面に出ない C0 は落とす）、タイムスタンプ無し。ローテートは設定の `rotate_bytes` と `rotate_keep` に従う。

ヘルプはコマンド一覧のオーバーレイである。Esc または `?` で閉じる。`q` は終了する。それ以外のキーは捨てる。

終了は、ログを flush してポートを切り、代替スクリーンと raw モードとマウスキャプチャとブラケットペーストを戻してからプロセスを終える。終了コードは 0 である。

## 7. キー、リサイズ、復帰、Windows、スレッド

### 7.1 キーからバイト

通常モードの打鍵は `KeyInput` にして `Session::apply_input` へ渡す。コアの対応表は v6 のままである。

| 打鍵 | バイト |
| --- | --- |
| Enter | 送信改行（既定 CR） |
| Backspace | `0x08` |
| Tab | `0x09` |
| Esc | `0x1B` |
| Ctrl+英字 | `0x01`〜`0x1A`。プレフィックスの文字は通常モードでは送らない |
| 矢印 | 通常 `ESC [ A/B/C/D`。アプリケーションカーソルモード中は `ESC O A/B/C/D` |
| Home / End | `ESC [ H` / `ESC [ F` |
| Delete | `ESC [ 3 ~` |
| F1〜F4 | `ESC O P/Q/R/S` |
| F5〜F12 | `ESC [ 15/17/18/19/20/21/23/24 ~` |
| Alt+文字 | `ESC` のあとにその文字のエンコード |
| 文字（IME の確定を含む） | セッションのエンコーディング。表せなければ送らず、状態行に理由 |
| Paste | `Input::Text` |

キーの離すイベントは無視する。リピートは送る。Ctrl+C は終了ではなく `0x03` である。終了はプレフィックスの次の `q` だけである。

### 7.2 リサイズ

起動時と `Resize` のたびに、端末領域（全体の高さから状態行の 1 を引いた値、最低 1）へ `Session::resize` する。幅も最低 1 である。

### 7.3 端末の復帰

入るときに raw モード、代替スクリーン、マウスキャプチャ（ボタンとホイール）、ブラケットペーストを有効にする。`Drop` で逆を行う。パニックフックでも同じ復帰を行う。フックのあと、元のフックを呼ぶ。

### 7.4 Windows

リリースビルドでもコンソールサブシステムにする。`windows_subsystem = "windows"` は付けない。仮想端末処理の有効化は crossterm が行う。Windows Terminal と、VT を有効にできる conhost を対象にする。

### 7.5 スレッドとバックプレッシャ

オープンは UI を止めない。`begin_connect` のあと、別スレッドが `PendingOpen::open` を行い、UI はチャネルを `try_recv` して `finish_connect` する。切断が先に来たオープンは `Cancelled` である。

ポートごとに OS スレッドが 1 つである。読んだバイトは深さ 256 の有界チャネルへ入れる（1 チャンク最大 4096 バイトなので、待ちは最大約 1 MiB）。チャネルが満杯のとき、スレッドは送れるまで待つ。待ちのあいだもコマンドチャネルを見る。`Shutdown` かコマンド送信側の切断で、待たずにスレッドは終わる。したがって切断は UI スレッドをブロックしない。

満杯のあいだはポートを読まない。カーネルのバッファが満杯になれば、書き手側がブロックする。バイトは捨てない。`IoEvent::Dropped` は残すが、この経路では出さない。状態（`PortLost`、適用失敗、ピン、コマンド失敗）は別の非有界チャネルなので、データ待ちに埋まらない。

UI は 1 フレームあたり最大 512 KiB の受信を画面とログへ適用し、それから 1 回描く。残りはチャネルに残る。次のフレームで続きを適用する。描画が遅れても欠落にはしない。

約 1 秒に 1 回 `Session::tick` を呼び、静かなログを flush し、終わったポートスレッドを回収する。

## 8. 不具合

GUI QA（D-261111-2）のうち、コアに原因があるものを直す。パレットとペインの不具合（B1〜B4、クリックの貫通）は、その UI を削除することで消える。任意パスに接続できない問題は、ポートピッカーが入力したパスを開くことで消える。

### 8.1 ログディレクトリ

原因は、ログディレクトリの解決が `LOCALAPPDATA` だけを見ていたことである。Linux ではこの環境変数が空なので、テキストログを開始できない。

解決順は次のとおりである。

1. `settings.toml` の `log.directory` が空でなければそれ。
2. OS ごとのディレクトリ。Windows は `LOCALAPPDATA/rs-term/logs`。Linux は `XDG_STATE_HOME/rs-term/logs`、無ければ `HOME/.local/state/rs-term/logs`。macOS は `HOME/Library/Logs/rs-term`。
3. どれも無ければ OS の一時ディレクトリの `rs-term/logs`。

`LOCALAPPDATA` が空であること自体は、Linux ではエラーにしない。

### 8.2 使用中ポート

原因は、`serialport` 4.10 が POSIX の `EBUSY`（TIOCEXCL の失敗を含む）と排他ロックの失敗を `ErrorKind::NoDevice` にまとめることである。表示側は `NoDevice` を無条件に「ポートが見つからない」と訳していた。OS の説明は `Device or resource busy` や `Unable to acquire exclusive lock on serial port` のまま残る。

説明文に `busy`、`ebusy`、`lock` が含まれるとき、または `io::ErrorKind::ResourceBusy` のときは、「ポートは使用中（他のプロセスが開いている）」と訳す。OS の説明は今までどおり括弧に残す。説明が空の `NoDevice` は、今までどおり「見つからない」である。

### 8.3 受信の欠落

原因は、受信チャネル（深さ 32）が満杯のとき `try_send` が失敗し、そのチャンクを捨てて `Dropped` を出していたことである。UI が描画で遅れ、pty が小チャンクを連続で書くと、2000 行のうち画面に残るのは数百行になる。

§7.5 のバックプレッシャに変える。テストは、モックポートから約 1 MiB を読み、捨てずに同じバイト列が届くことを確認する。

### 8.4 スクロールバック

原因は、画面側に `scroll_lines` があるのに、GUI がホイールをそこに繋いでいなかったことである。TUI は §5 のとおり繋ぐ。単体テストは、画面より多い行を流したあと履歴方向へスクロールし、先頭付近の行が見えることを確認する。

## 9. パス

設定ファイルは次のディレクトリの `settings.toml` である。ディレクトリが決まらなければファイルは読まない。

| OS | ディレクトリ |
| --- | --- |
| Windows | `%APPDATA%/rs-term` |
| Linux | `$XDG_CONFIG_HOME/rs-term`、無ければ `$HOME/.config/rs-term` |
| macOS | `$HOME/Library/Application Support/rs-term` |

ログディレクトリは §8.1 である。解決はコアの関数にし、環境変数は引数で渡せるようにする。テストは OS の実環境に依存しない。

## 10. 文言と著作権

利用者が見る文は日本語である。CLI の使い方、状態行、ダイアログ、エラーを含む。コアの既存の文のうち、ペインや `Ctrl+Shift+K` を案内するものは、この TUI の操作（プレフィックスの次の `c`、ログ停止）に合わせて書き換える。

著作権表示は sotola122 のままである。`README.md` に TUI の起動例、プレフィックス、状態行、ログの場所を書く。`NOTICE` から gpui 系を外し、ratatui と crossterm を書く。

## 11. CI

`test.yml`、`build.yml`、`release.yml` の分割は維持する。Linux のシステム依存から、X11、Wayland、xkbcommon、fontconfig、Vulkan を外す。`pkg-config` と `libudev-dev` は `serialport` の列挙に必要なので残す。

## 12. テスト

コアで、ログパスの解決、使用中エラーの翻訳、スクロールバック、約 1 MiB の無欠落受信。フロントエンドで、CLI の解析、キーからバイト、プレフィックスの分配、状態行の描画（ratatui の `TestBackend`）。

Linux では pty のループバックに対してバイナリを動かす。確認するのは、打鍵のエコー、Shift_JIS と ANSI 色、2000 行のバーストで最終行が残ること、スクロールバック、ログファイル、終了後に代替スクリーンを抜けていることである。
